# Руководство по внесению изменений

## Как предложить изменение

1. Обновите локальную ветку `main`.
2. Создайте отдельную ветку для изменения.
3. Внесите изменения в Markdown-файлы в каталоге `docs/`.
4. При необходимости обновите `mkdocs.yml`.
5. Запустите локальную проверку.
6. Создайте коммит в формате Conventional Commits.
7. Отправьте ветку на GitHub и создайте Pull Request в `main`.
8. Исправьте замечания ревьюера и дождитесь одобрения.
9. Выполните merge только после успешного CI.

## Имена веток

Используйте короткие имена, описывающие изменение:

- `docs/accessibility`;
- `docs/terminology-update`;
- `fix/navigation`.

## Conventional Commits

Формат:

```text
<type>: <краткое описание>
```

Для документации используйте в первую очередь `docs`.

Примеры:

```text
docs: add accessibility guidelines
docs: clarify terminology rules
fix: correct MkDocs navigation
ci: add documentation checks
```

## Локальная проверка

Установите зависимости:

```bash
pip install -r requirements.txt
```

Проверьте сборку:

```bash
mkdocs build --strict
```

Для локального предпросмотра:

```bash
mkdocs serve
```

Markdown также проверяется автоматически в GitHub Actions.

## Процесс ревью

Pull Request должен:

- описывать цель изменения;
- содержать только относящиеся к задаче изменения;
- проходить CI без ошибок;
- быть просмотрен как минимум одним участником учебного ревью, если это требует задание.

Ревьюер проверяет содержание, структуру, единообразие терминологии, читаемость и корректность навигации.

## Как добавить новый раздел

1. Создайте файл `docs/<section-name>.md`.
2. Добавьте заголовок первого уровня `# Название раздела`.
3. Заполните раздел правилами и примерами.
4. Добавьте файл в `nav` внутри `mkdocs.yml`.
5. Запустите `mkdocs build --strict`.
6. Создайте коммит и Pull Request.
